# Read-only disposable recovery snapshot

`readOwnedDisposableArtifactRecoverySnapshot` accepts the exact native task,
registration selection and original preview digest. Caller paths, snapshots,
signing proof and filesystem bindings are rejected by the native selection reader.
This API creates no files, locks, keys, receipts or progress and removes no data.

The reader composes the authenticated owner/intent and progress APIs, then scans
current queue, timeline, raw-evidence, WIP and worker dependencies. The existing
preview digest algorithm reconstructs the original digest using those real native
dependencies, native owners, committed closeout and the signed original inventory.
Any dependency drift or surviving raw-content reference preserves the selection.

Each surviving root is inventoried through the existing bounded contained tree
reader. Remaining paths must match the original inventory minus the signed
successful prefix and, optionally, one exact unresolved PENDING absence. Ordinary
creation bindings, file stat and byte hashes, directory membership and signed
REMOVED parent stat identities must still match. Unknown absence, replacement,
new entries, symlinks and changed bytes are rejected without writes.

An absent pending member remains unresolved and does not increase successful
counts. Its direct parent may have the changed full stat caused by that uncertain
unlink; its creation and exact selected membership remain verified, and its fresh
stat is bound for publication. Other directory and signed parent identities stay
enforced. A pending absent root requires the authenticated surviving-parent anchor;
unsupported legacy absence remains rejected by the existing authority reader.

The returned snapshot reports exact observed remaining files/bytes, signed known
successful counts and `pending_absent_path`. Every result has
`absence_authorized: false`. Recovery/removal must reconstruct proof under native
lifecycle and producer locks; this read-only snapshot cannot authorize a mutation.
Current native metadata, remaining/absent bindings, parent generations and all
dependency bytes are rechecked before returning.

Validation covers real native partial, pending, error, finished and multiple-root
states, unknown absence, same-byte replacements, changed membership/bytes,
dependency and private-authority drift, copied/corrupt progress and publication
races. Native Linux execution is validated in the task gates; Windows, WSL and
browser execution are not claimed.
