# Language-independent boundary source bindings

Boundary source evidence can capture the existing explicit `source#case` references without a project declaration, a language parser, English case wording or a conventional test directory. The common matrix normalizer retains required boundary fields and duplicate-boundary checks.

The binder captures contained regular-file identities, retains every exact opaque case, optionally checks the exact prior source identity set, and revalidates unique sources before returning. Shared sources count once against the existing 8 MiB input budget; the 128-reference limit remains unchanged. The retained digest includes the matrix and source/case bindings.

`BOUND` describes structure and source identity only. Every source remains `UNRESOLVED`, with semantics `PENDING_INDEPENDENT_REVIEW`. No execution observation, test outcome, grant or review receipt is created. Missing, ambiguous, substituted and out-of-root sources remain invalid.

This prerequisite does not activate the ordinary workflow by itself. T-259 still requires authenticated command evidence, independent case resolution and the complete normal quality/review/terminal chain. Qualification fixtures represent Java/JUnit, JavaScript and unfamiliar source bytes; they do not claim execution or acceptance of OnlineStore.
