# Decomposed-parent audit requirements

The pure `deriveDecomposedParentAuditRequirements` API plans aggregate obligations;
it cannot return PASS or change lifecycle state. Ordinary leaves remain outside
this contract. A completed-looking parent still requires authenticated decomposition,
source-qualified child acceptance and preserved parent WIP. Original suite failures
retain a composition requirement even when the current suite is disabled. Required
or unknown parent memory applicability and every historical failure remain obligations.

Inputs are projections, not authority. The owning caller must reconstruct current
events, the complete explicit child graph and applicability from native evidence;
reference shape and sequence validation do not authenticate them. Missing, foreign,
corrupt or inconsistent projections block planning. Producer and audit integration
remain separate packages; this child alone does not unblock a consumer parent audit.
