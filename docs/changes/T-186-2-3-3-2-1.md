# Authenticated disposable progress metadata

`readOwnedDisposableArtifactRecoveryProgress` reads the canonical progress storage
for an exact native task, registration selection and confirmed preview digest.
It accepts selection fields only. Paths, snapshots, signing proof and keys cannot
be supplied by the caller.

The shared journal transport bounds total progress bytes to 4 MiB and directory
entries to 4098. It validates ordinary file creation, exact outer schema, the
distinct progress HMAC purpose and the existing private authority generation.
Sequential canonical filenames form an exact directory inventory; copied files,
unknown temporary metadata, gaps and changing storage remain protected.

The decoder derives the producer's removal order through the shared pure order
helper. Each frame must bind the original intent hash, ownership digest, sequence,
previous frame hash and exact member. Counters must equal the successful signed
member prefix. REMOVED requires its PENDING frame and a signed parent identity.
ERROR and FINISHED settle this first-apply metadata chain; later frames reject.
Unsupported historical progress formats remain preserved for diagnosis.

Returned states are UNSTARTED, PENDING, PARTIAL, ERROR and FINISHED. A pending
member does not count as successful removal, even if its payload is absent.
Every result explicitly returns `absence_authorized: false`. This reader does not
prove current remaining payload bytes or dependencies and cannot authorize resume.
Those requirements belong to the subsequent snapshot and mutation work packages.

The reader repeats native owner/run, committed compact evidence, key/intent and
progress storage checks before returning. It creates no private authority,
removes no metadata and writes no payload.

Validation covers real first-apply completion and EACCES partial progress,
multiple registrations, a retained signed pending prefix, malformed authenticated
state, copied frames, wrong purpose, unknown/gapped/excess storage, single and
aggregate byte limits, key loss/replacement, a directory appearing during an
absent read and rejected caller proof. Execution coverage is native Linux; native
Windows, WSL and browser execution are not claimed.
