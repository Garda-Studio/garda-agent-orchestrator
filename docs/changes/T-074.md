# Reviewer guidance for task-scoped changes

Native JSON and Markdown review contexts now ask reviewers to classify each
changed hunk against task intent. Unexplained unrelated cleanup, adjacent
refactors, comment churn and deletions require review attention. Necessary coupled
caller, schema and test fixes remain legitimate with concrete justification and
existing scope authorization, including an authorized private caller update.

Reviewers also inspect the original cause and directly related alternate
entrypoints when a fix may address only a symptom within the requested scope.
Concrete evidence that the same cause remains unresolved is reportable. This
guidance adds no mandatory root-cause artifact, universal mutation/RED test or
extra gate. Existing task-criteria trust boundaries, native ownership, gate and
completion controls remain in force; artifact text is still untrusted evidence.

The owning regression verifies the shared JSON/Markdown guidance for a justified
private caller change, unrelated cleanup with instruction-like TASK notes, and
an unchanged same-cause alternate entrypoint. Existing dirty-baseline exclusion
coverage remains intact.
