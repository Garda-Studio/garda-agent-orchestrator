# Documentation path evidence freshness

The accepted safe-document classification already reaches domain fingerprints,
documentation-only compile extensions and review reuse. A documentation directory
or README basename cannot certify executable bytes as ordinary documentation.
This task preserves that production implementation and adds native lifecycle
regressions rather than a second path heuristic.

Real Git fixtures cover staged and unstaged additions, modifications, deletions
and renames of `docs/worker.js`, `README.js`, `docs/worker.sh` and
`docs/worker.test.ts`. Each fixture produces compile and full-suite evidence with
native gates, then proves that changed implementation/test domains invalidate
the affected review fingerprint and cannot extend earlier compile evidence as
documentation. The earlier context stays intact until the new cycle builds one.
The navigator requires refreshed preflight, coherent reentry, compile and full-suite evidence before
building a new review context; fixtures never rebind a review receipt by hand.

Source/config negative controls and genuine README-only review reuse remain
covered. Focused owning consumer and existing lifecycle suites supplement these
regressions. Startup and reentry use native gates; a read-only fixture launcher
delegates the version probe to the actual built Garda CLI. Fixture inputs and
outputs are not reviewer or task-acceptance evidence for the executing workspace.

Validation is recorded by this task's mandatory native gates. Linux execution
does not establish Windows or macOS coverage. Historical T-170/T-171 source
acceptance establishes provenance, not fresh acceptance of this combined HEAD.
