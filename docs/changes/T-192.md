# T-192: Interrupted mutation journal publication

The existing slot/head/anchor journal keeps the anchor as the authority for the
current generation. A valid adjacent, unpublished BEGIN, COMMIT or ABORT can be
checked against that anchored state without accepting it as a new committed
generation. Missing, corrupt, discontinuous or rolled-back authority still fails
closed; journal schema and lock ownership rules are unchanged.

An anchor-write failure followed by a retry head-write failure can leave an
unpublished head naming the prior candidate's hash. Recovery still requires an
exact anchor match for the previous state and a fully valid adjacent transition;
it does not accept the replaced candidate as committed. A head naming a different
state hash at the anchored sequence remains corrupt even if its metadata hashes
are internally consistent.

When COMMIT or ABORT publication is interrupted, the original active ticket can
retry settlement. Readers remain BUSY until that ticket is settled. A repeat of
the latest anchored settlement acknowledges the same ticket, kind and outcome
without advancing generation twice. A different kind, opposite outcome or ticket
superseded by later transitions is rejected. This is a bounded retry window, not
an unbounded history of completed tickets.

Lifecycle wrappers retry settlement once using the original ticket. They do not
rerun the operation that changed canonical files. Recovered publication preserves
the original operation error; an exhausted retry preserves both settlement errors
and the active BUSY state.

Affected checks cover failures at slot, head and anchor writes for all three
transition types, mixed anchor-then-head failures, ticket identity and replay,
forged unpublished settlement and inconsistent anchored head bindings,
existing rollback and symlink rejection, real process contention and lifecycle
partial-write/error handling. The lifecycle writer seal is refreshed against the
integrated source inventory; purge writer checks reuse existing healthy-completion
fixtures and verify generation increases beyond the fixture's initial writes.
Native validation and independent review receipts provide execution results.
Windows-specific filesystem and lock acceptance remains unverified in this Linux
workspace.

## Local source integration boundary

The accepted runtime journal implementation is integrated with its owning tests.
The separate lifecycle settlement wrapper and its writer-inventory regression
remain preserved for composition review against the later root cleanup source.
This partial integration does not establish the full lifecycle wrapper behavior
or native acceptance of the original parent. Original producer bytes, reviews
and source history are retained separately.
