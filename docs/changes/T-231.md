# Exact follow-up task references

Review follow-up materialization uses the shared exact task-ID reference matcher
when deciding whether parent notes already link a child. An existing F10 reference
therefore cannot suppress recovery of F1, including when the authenticated artifact
and child row already exist. Repeating the same materialization after recovery
preserves the task queue bytes.

Insertion uses the existing direct numeric follow-up predicate. Rows such as
T-9-Future and T-9-F1-I1 cannot move the insertion point for T-9-F1, and T-90 remains
independent of T-9. Ordinary numeric and nested infrastructure children retain
their existing parsing behavior; review follow-up grouping still selects direct
F-number children only.

This changes no artifact schema, finding binding, receipt validation, task profile,
authorization, transaction or rollback contract. Regression checks exercise the
public materialization/recovery path, same-artifact idempotence, preservation of
foreign rows, and the existing decomposed-child parser through affected Node tests.
