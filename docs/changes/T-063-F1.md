# Backup deletion inventory refresh regressions

The owning backend and CLI suites now deny the final inventory read only after
the selected snapshot has been completely removed. The regression verifies that
successful removal IDs and exact freed-byte accounting survive an inventory
refresh failure, while `inventoryRefreshed` stays false and `inventoryError`
retains the original failure. The unavailable inventory remains empty and does
not imply that unrelated snapshots were removed.

Both JSON and text CLI output must report the refresh failure and return a
non-zero exit code while preserving successful deletion details. Fresh inventory
reads after the injected failure verify that unselected snapshots and their
payload bytes remain unchanged. Production deletion, containment and permission
guards are unchanged.

Affected validation targets are `tests/node/lifecycle/backups.test.ts` and
`tests/node/cli/commands/backup-command.test.ts` through the audited native full
suite gate. The linked regression closes the previously deferred inventory
refresh coverage gap; it does not complete the preserved disposable crash-marker
follow-up or another owner's UI consumer validation.
