# Required built-in review snapshot activity

Effective review snapshot validation now follows the existing profile policy:
a built-in lane with profile state `required` remains active even when its review
capability flag is false. A canonical snapshot produced from that policy therefore
passes structural validation and frozen-policy reconstruction without changing
the capability or installing a skill pack as a workaround.

The exception is limited to required built-in profile lanes. Disabled or automatic
built-in lanes still depend on their original profile and capability controls;
required custom lanes and explicit task-required declarations retain their
capability checks. Contextual selection, zero-diff suppression, catalog identity,
snapshot hashes and frozen policy bindings remain enforced.

Regression tests cover every built-in required lane with disabled capability,
canonical reconstruction and zero-diff, inactive controls, self-rehashed activity
forgery, custom capability refusal and substituted built-in or policy bindings.
