# Grouped follow-up publication with three fresh lanes

Grouped materialization may publish independently authenticated fresh deferred
lanes sequentially into one pending child when another fresh lane has not yet
published its follow-up artifact. Registry validation reconstructs each lane's
receipt, invocation, validation and disposition before granting this bounded
publication-phase treatment.

Existing files, unsafe destinations, registered missing artifacts and reused
lanes retain their integrity requirements. Default discovery and child scope
admission still require every authenticated deferred lane to be fully published.
No receipt, historical cycle, task status or consumer runtime is rewritten.

The owning regression exercises all six publication orders for security,
refactor and test, keeps child scope invalid through partial publication, and
checks missing registered and forged pending proof inputs alongside the existing
historical/reuse/foreign/tamper suite. Linux validation is performed through the
native affected gates; Windows and macOS execution remain unverified.
