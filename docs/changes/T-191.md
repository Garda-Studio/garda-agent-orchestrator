# T-191: Fail closed on invalid full-suite configuration

The shared core and gate configuration reader now rejects unreadable or non-file
configuration paths (including invalid deployed-bundle ancestry before fallback),
malformed JSON, non-object roots or sections, and invalid explicit full-suite fields.
These failures propagate to callers before disabled
or successful full-suite evidence can be emitted. JSON diagnostics omit the
configuration contents.

A genuinely absent configuration file or section and omitted fields retain their
existing defaults. Supported scalar aliases use the shared boolean and integer
normalizers; commands remain trimmed, timeout values remain positive integers
(including existing sub-second runtime values), and retry limits remain unchanged.
Explicit invalid values are rejected even when validation is disabled.

Focused regressions cover the shared reader and CLI failure path, valid defaults
and aliases, malformed field values (including singleton placement arrays),
directory and invalid ancestor paths, dangling file, directory and deployed-bundle
symlinks (including recognized bundle-name casing), invalid configuration beneath
valid case-variant links, ambiguous fallback deployment paths, valid linked-bundle
and standalone-root configuration, and missing files beneath valid directory symlinks.
The POSIX permission case requires a non-root process and is
skipped when that permission boundary is unavailable. The native affected suite
also covers command contracts, duration forecasts, navigator placement and
routing, completion evidence, and configuration artifact schemas.
