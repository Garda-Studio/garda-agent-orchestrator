# Bounded disputed lock preservation

`preserveDisputedLockDirectory` retains the claimed directory and copies it into `<project-parent>/garda-recovery-preserved/lock-claims/<uuid>`. This owner-managed sibling is outside runtime, scratch, retention backups and cleanup candidates; retain originals and captures until operator-verified custody and recovery compatibility.

Admission allows a flat ordinary directory with at most 64 members and 1 MiB total; links, shared files, nested directories, unsupported objects, missing creation identity, drift and budget overflow fail closed. Failures retain original and partial captures; the claimed directory and canonical owner path remain unchanged. Metadata records bytes, hashes and source identities without granting ownership or recovery authority. Filesystem-root projects are refused. Storage identity is bound before owner/write-permission checks and revalidated before and after capture creation. After byte verification, a final signature sweep checks every source file, copy and manifest, followed by directory identity, membership and containment checks.

The dependent integration must report restoration conflicts; copying fails closed without a supported storage-owner check. Linux evidence and Windows validation remain separate. No addon, binary, compiler, subprocess backend or build hook is introduced.
