# Portable full-suite marker publication

Issued marker handles keep the private process-local capability, parent binding,
physical generation identity and exact expected JSON. They no longer retain an
open marker descriptor between API operations or across namespace mutations.
Windows can refuse atomic replacement or parent-directory renames while a marker
descriptor remains open; no alternate publication primitive is introduced.

Exclusive creation still writes and fsyncs through its original descriptor.
Bounded read probes validate an ordinary single-link generation before opening,
against the held descriptor and canonical path during the read, and again after
closing. Identity or size/time drift rejects mutation. Available no-follow and
nonblocking flags prevent linked or special-file reads from becoming authority.
Complete child JSON still publishes with one same-directory atomic rename;
publication failures preserve the current marker and allow an owner retry.
Foreign generations, content and parent replacements remain untouched. Serialized
JSON, forged handles and old handles still cannot authorize update or cleanup.

The existing mutation lock coordinates cooperating writers. Arbitrary external
replacement between final path validation and a namespace syscall is not an OS
compare-and-swap guarantee. Schema-1 inspection and native recovery are unchanged.

Linux regression includes descriptor-lifetime fault injection and drift during
probe closure, alongside the existing negative owner and CLI cases. Root must
verify the real Windows Node 24.11.1 behavior; Linux mocks are not Windows acceptance.
