# Codex reviewer launch interface guidance

Provider metadata and shared reviewer instructions now consult the current
Codex client's declared tool schema. When `collaboration.spawn_agent` is exposed,
they select `fork_turns="none"`; another client uses only its exposed isolation
option. The guidance no longer requires the legacy universal
`multi_agent_v1.spawn_agent` namespace.

The existing exact native launch input, fresh context, real invocation identity,
immediate delegation-start recording, post-return finalization, validated
receipt and reviewer release contracts remain in force. Provider identity,
`SourceOfTruth`, model selection, delegation policy tiers and review admission
or authentication logic are unchanged.

Registry tests and generated shared-router/full/compact bridge tests cover
conditional isolation and negative legacy-tool drift. The affected provider
entrypoint-minimalism suite also checks the selected-provider setup boundary.
`docs/provider-client-evidence.md` separates the observed session interface from
unknown desktop version and unprobed CLI/IDE/cloud and other-provider behavior.
No hosted CI, publication or paid compatibility probe is part of this child.

The local managed start-task router carries the matching instruction text.
Native completion, review and command results remain owner-local evidence;
this document alone does not claim task acceptance or completion of the broader
provider compatibility parent.
