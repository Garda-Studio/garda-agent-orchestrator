# T-153-9-2: Architecture guidance follows actual failure boundaries

The architecture-review lens distinguishes local in-process call chains from network, database and cross-process I/O. Local chains are reviewed against input/output, error, ordering, ownership and resource-cost invariants. A fixed hop count alone cannot require an asynchronous boundary or distributed timeout/retry machinery.

Remote calls retain failure-mode analysis, one end-to-end deadline, remaining-budget and cancellation propagation, safe retries, and appropriate fallback or isolation. Examples show a three-hop local chain and a remote pricing/inventory chain whose downstream timeouts cannot extend the original request deadline.

The canonical skill and checklist have byte-matching shipped live mirrors. The native materialization/scenario fixture covers both boundary types and preserves the existing refactor contracts, custom skills and project memory. Generated architecture-review handoffs retain their findings-only, read-only instruction/output authority. No production gates, suite policy or architecture standards change.
