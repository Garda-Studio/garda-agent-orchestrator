# Confirmed Disposable Recovery

The public `resumeOwnedDisposableArtifacts` contract accepts only the existing
exact native selection and `confirmed: true`. It reconstructs current signed
intent, owner/run, compact committed evidence, retained progress, remaining
membership, dependencies and ordinary identities. Unfinished recovery executes
through the accepted lifecycle/producer-locked metadata gateway.

Only gateway-issued exact entries are removed, nonrecursively, with parent fsync
and native signed REMOVED publication. An inherited unresolved pending absence
is reconciled once under native proof. A new pending disappearance before issue
stays incomplete with readable error history; a later invocation may reconcile
that inherited uncertainty. Caller paths, snapshots, records and signing keys
cannot provide authority.

The response distinguishes the initial verified historical removed and
reconciled prefix from this invocation's actual successful unlink/rmdir counts
and conservatively reconciled absence. An interrupted unlink or failed metadata
publication never becomes a complete-success count. `counts_complete` is true
only after an authenticated terminal proof. Unknown historical or remaining
counts are null on blocked admission. Reconciled bytes describe the signed
inventory of an inherited absence, not proof of a current unlink.

Canonical FINISHED inspection returns `already_finished: true` without payload,
lock, runtime-generation or progress writes. It uses the supported native review
read snapshot for compact audit proof; mutation reconstructs fresh authority
outside that read context. Active completion still uses fresh
locked proof; pending/error and actual partial counts remain visible on failure.
Unknown, corrupt or interrupted metadata, changed paths, current dependencies,
key/run/owner drift and actual lock loss preserve diagnostics and surviving data.
An ambiguous unlink refusal remains blocked in the same process. A fresh process
may resume only after reconstructing the unchanged native proof; recovery does
not clear or bypass containment's in-process rejected-path guard.

Tests use native fixture producers and retained metadata. Real Linux workers are
SIGKILLed after durable PENDING, after an actual unlink, and after the last durable
REMOVED before creating FINISHED. Parent tests prove real PID death and native
known-dead lock reclaim, complete eligible payload absence, separate byte counts,
immutable original compact hashes and frame prefixes, and a repeat without new
frames. Other tests cover legacy partial/error/pending states, multiple producers,
unknown/replaced payload, authority/dependency drift, failed unlink/publication,
corrupt/interrupted metadata, lock loss and same-attempt pending disappearance.

The affected suite retains mutation/snapshot/progress/authority, first-apply
removal/journal, preview/registration, ownership and containment regressions.
Windows, WSL, browser and CI coverage remains unverified. This leaf adds no
producer, closeout, CLI, raw-evidence migration or worktree wiring.
