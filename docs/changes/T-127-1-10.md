# Protected control setting definitions

The typed core family at `src/core/workflow-settings/protected-controls.ts` owns
the three existing task-reset, local-commit and Garda self-guard definitions.
The report adapter retains their stable ids, keys, CLI flags, descriptions,
boolean/mode choices, self-guard read-only hint and original catalog positions.

Defaults remain OFF for task reset and local commit, and `deny_agent_entry` for
protected control-plane work. Typed candidates admit canonical booleans or modes
through the unchanged public workflow validator, then return one immutable field
change for either live or template. Existing persisted-config aliases are
unchanged. Presentation options are detached from validation authority.

Candidates are not permission publication. The family does not write settings,
issue signed reset authority, grant native commits, alter protected entry,
perform reset/commit actions or handle private keys. Specialized guarded owners
remain responsible for actual mutations. A workspace's separately authenticated
commit ON is independent of the canonical OFF default.

Owning family and adapter tests cover defaults, exact flags, parser compatibility,
invalid primitives/modes/targets, immutable output, presentation isolation and
the independent complete 61-definition catalog digest. Affected checks also
cover the existing reset authority/flow and audited commit/workflow policy owners.
