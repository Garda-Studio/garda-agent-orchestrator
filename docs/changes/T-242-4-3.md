# Recipe-based expected-red navigation

For an admitted project-validation contract, the navigator selects a declared eligible test recipe rather than deriving a runner from file extensions. Current native test-only classification, the exact TASK declaration and frozen recipe authority remain required.

Implementation is offered only after the existing canonical result reader authenticates a genuine EXPECTED_FAILURE from the latest recipe attempt in the current task cycle. Changed source/output/results, unexpected pass, opaque output, interrupted attempts and stale evidence do not advance the navigator. No recipe executes during navigation. Projects without recipe authority retain the existing legacy route.

Validation covers extensionless declared tests under an authenticated custom test-path policy, actual native failure evaluation, altered and superseded results, unsupported output and changed helper identity, plus the existing legacy routing tests. Classification-policy activation and terminal acceptance remain separate T-242 obligations.
