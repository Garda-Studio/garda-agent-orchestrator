# Typed legacy scope-budget maximum metadata

The four existing `scope_budget_guard.max_*` definitions now belong to
`src/core/workflow-settings/scope-budget-thresholds.ts`. Their read-only report
projection retains all stable ids, keys, flags, labels, descriptions, scalar
bounds and contiguous catalog order. The independent complete 61-setting
digest continues to cover every presentation field.

Canonical defaults come from the existing workflow owner. Typed candidate
admission accepts safe integers within the existing presentation bounds and
reuses `normalizeScopeBudgetGuardConfig` for the selected field. Public
CLI/config parsing and specialized cross-field normalization are unchanged.
The remaining eleven scope-budget controls retain their existing owners.

Live/template materialization returns only the requested frozen `max_*`
candidate. It neither writes configuration nor rewrites warning/block
thresholds, profiles, action mapping, task policy, grants or evidence. Existing
guarded writers and warning/block evaluation remain authoritative.

Owning tests cover all four definitions and default identities, lower/upper
boundaries, invalid scalar values, target restrictions, frozen candidates,
unchanged owner defaults and presentation mutation isolation. Foundation,
report metadata/localization, workflow-config and existing scope-budget guard
tests cover the unchanged consumers and legacy threshold semantics.
