# Disposable artifact producer registration

The lifecycle facade exposes `registerOwnedDisposableArtifact`,
`inspectOwnedDisposableArtifact` and `sealOwnedDisposableArtifact`.
Each call requires the canonical workspace and bundle roots plus an exact task id.
Registration also requires a declared category; inspection and sealing require
the returned registration id. Arbitrary payload paths, worker identities and
additional input fields are rejected.

Registration creates a fresh payload directory under
`runtime/owned-disposable/<task-id>/<native-run-id>/<registration-id>/`.
Supported categories are raw stdout, raw stderr, coverage intermediates,
temporary source, test and build trees, and diagnostic archives. Producers write
only disposable content into that returned root, then seal their registration
before exiting. Only the original local process, host and in-memory producer
execution instance may seal it. Repeated sealing by that producer is idempotent
within the same native run. A fresh module/worker execution instance cannot take
over an interrupted registration, even when its numeric PID is reused.

Producer records and their private authority remain separate under
`runtime/disposable-producers/`. The record binds the canonical workspace's
creation identity, current native task-mode bytes and entry event, exact task,
category, producer process, host and execution instance, fresh payload creation
identity, and seal time. The authority is created exclusively with private mode
before any authentication bytes are written; interrupted partial keys remain
private and fail closed. The existing complete pathname identity helper handles
Windows pathname stats that omit the device id without weakening identity checks.
HMAC authentication detects altered public records; copied records and keys
do not establish ownership in a different workspace. This local procedural
boundary does not protect against an actor able to replace private authority or
execute arbitrary code as the workspace owner.

Inspection is read-only and bounded. Missing, linked, shared, oversized, changed
or unauthenticated metadata, substituted roots and stale native runs fail closed.
It reports live only for the same proven local execution instance. A currently
occupied remote producer PID is unknown because its process generation cannot
be proved; an absent local PID is dead. Foreign hosts remain foreign. These
states never adopt a root or infer eligibility. Interrupted registrations and payloads remain available
for diagnosis; missing authority is never recreated by inspection or silently
replaced in a populated registry.

If the seal clock precedes registration, sealing rejects before publication and
preserves the unsealed owner bytes. The original producer can retry after clock
recovery; timestamps are never clamped or synthesized.

Mutations reuse the lifecycle lock, shared scratch writer lock and runtime
mutation-generation API. Ordinary retention and task purge exclude both these
namespaces. Registration and sealing never remove payload or establish cleanup
eligibility. Compact migration, terminal acceptance, dependency checks, nested
Git protection and resumable removal belong to the separate cleanup transaction.

Validation covers actual filesystem roots, all categories, native run changes,
record forgery, copied workspace state, links, shared files, replacement, bounded
read races, missing authority, omitted Windows pathname device ids and backward
seal clocks. The Windows stat case is simulated on Linux. Native Linux is the current
executed platform; Windows behavior requires its own native checks.
