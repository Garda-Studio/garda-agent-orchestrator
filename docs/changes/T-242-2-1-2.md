# Technology-neutral validation declarations

Version 1 validation recipes declare literal executables and arguments, exact
input roles and test targets, canonical repository paths and bounded resources.
The parser preserves unfamiliar technologies and Unicode identities as data,
rejects malformed declarations and known startup environment selectors, including ZDOTDIR and HOME, and reuses the accepted command-data inspector.
Declared capabilities and future approval/snapshot types grant no execution
authority. Expected-red eligibility requires changed declared test roles, an
exact test target bound in argv and the supported case format; source-role aliases are rejected.
