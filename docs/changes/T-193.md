# T-193: Proven-dead mutation intent recovery

New BEGIN records carry an optional local owner identity. On Linux with an
available, coherent proc view, it binds hostname, kernel boot ID, PID namespace,
PID and process start ticks, with a separate observer time-namespace binding.
A reused live PID with different start ticks proves that the recorded process
generation ended only when the observer clock namespace is known and matches.
Different Linux time namespaces can render the same live process with different
start ticks; those records remain indeterminate. ESRCH proves absence after the
current host/boot/namespace scope is verified. Hostname alone and elapsed time
never authorize recovery. Missing proc, permission failures, ambiguous probes,
foreign scope, unsupported platforms and legacy records without owner identity
remain indeterminate and preserve their active intents. If clock identity is
unavailable, PID absence can still be proven in the verified boot/PID scope,
while a present PID's generation remains indeterminate.

The next journal BEGIN scans active intents under the existing generation lock.
Only proven-dead intents are settled, each through the existing COMMIT hash-chain
and slot/head/anchor publication contract. Recovery advances generation because
the exited owner may have persisted canonical bytes. It never repeats that
owner's callback. Live or indeterminate intents can coexist with new writers and
still keep public generation reads BUSY. Reads themselves remain read-only.

Schema-1 legacy intent bytes and earlier owner records without a clock binding
retain their original hash representation; no missing identity is invented.
New owner fields are strictly validated. Owner identity is
local kernel evidence within the journal's existing filesystem trust model, not
an external cryptographic attestation or a multi-host lease. Recovery retries use
the same authoritative anchor and transition checks as interrupted settlement.
The bounded state size is checked before publication so identity metadata cannot
produce an oversized, unreadable journal.

Affected checks include real exited/live owners, competing process recoverers,
PID-generation reuse, incomparable observer clocks, legacy/null/foreign ownership, permissions and hidden proc
entries, malformed owner data, read-only BUSY behavior, publication interruption,
state capacity and existing lifecycle writer/settlement regressions. Windows
execution is unavailable here. This Linux environment also exposes no time
namespace proc entry; an actual unshare capability probe returned EINVAL. Clock
scope and reuse fixtures are simulated where required; actual exited/live-owner
and competing-process checks do run. Conservative unsupported paths do not
establish Windows or real cross-time-namespace acceptance.
