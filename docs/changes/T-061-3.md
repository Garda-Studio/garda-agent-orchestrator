# T-061-3: exact task-erasure base preview

`previewTaskErasure({ targetRoot, taskIds })` is a read-only lifecycle API. It
requires exact canonical queue IDs, rejects duplicates, aliases, unknown IDs and
malformed queues, and keeps parent/child selection explicit. Surviving queue
references and unselected children block the affected selected task. Current,
stale or ambiguous runtime activity blocks selection even when TASK.md says DONE;
existing timelines must retain genuine native integrity evidence.
Authenticated restart/terminal event order is checked without an age cutoff:
an old terminal event cannot conceal later unfinished runtime activity.

The preview reuses registered task-purge collectors and authenticated retired-WIP
ownership. A bounded ordinary-file snapshot supplies exact file counts, bytes,
hashes and creation identities. Directory membership, canonical queue bytes and
statuses, shared runtime inputs and WIP classification bind the deterministic
ownership digest. Missing boundaries are bound as absence. Unreadable, changing,
linked or unrecognized selected ownership remains blocked rather than silently
becoming an empty inventory. Inspection conservatively snapshots the registered
runtime namespaces, so unrelated unreadable or oversized evidence in those
namespaces can also block admission; it is never deleted.

`READY` describes a consistent **base-domain preview**, not completed erasure or
permission to mutate. `mutation_authorized` and `full_erasure_complete` are always
false. Shared operations are reported without changing queue rows, aggregates,
indexes or metrics. Source, live settings, durable project knowledge and unrelated
evidence remain untouched. Generic scratch has its separate ownership API.

The `composition` contract requires `internal-recovery-copies` coverage from
T-061-4 and carries exact IDs plus the base ownership digest. This API does not
remove or rewrite recovery points, implement queue deletion/apply, or publish a
full-erasure success path. Subsequent apply must revalidate current authority and
selection under the owning locks; this unsigned in-memory digest alone grants no
deletion authority. External archives and Git history remain explicitly outside
the local domain; secure disk erasure is not claimed.

Validation starts with the genuine native expected-red public-export regression.
Owning cases cover exact selection, DONE/TODO/activity, surviving references,
immutable previews, digest drift, linked/unknown/unreadable ownership, forged
terminal evidence, shared operations and retained WIP. Native compile, affected
suite, fresh independent reviews and post-commit acceptance are still required.
