# T-207-2: action-scoped UI reset authority

Confirmed Reset task and Close without execution requests now run one native
`gate task-reset --one-action` command. The HTTP adapter checks the exact reset
or close confirmation phrase before adding fresh operator confirmation input.
Preview does not issue authority. Existing origin/token/content-type admission
and native task/scope/workspace/currentness guards remain in their owners.

Both global workflow-set preparation and restoration have been removed. A
reset no longer changes permanent `task_reset.enabled`, repairs missing policy
audit, or restores a stale policy boolean. Interrupted native preparation leaves
permanent OFF unchanged; a later explicit audited enable remains enabled.
Native failures remain failures in the HTTP response and action audit.

The accepted dependency is C5 T-207-2-R1, imported and independently accepted in
C3 T-207-C3-I3 / `7da6757b4cf1201ae1b2f4c42df7e149ac428b68`.
Two original expected-red lifetime regressions were reproduced before adapter
changes. Owning HTTP tests cover preview, wrong confirmation, reopen/close
commands and native failures. Linux checks are executed locally; Windows
execution remains unverified.
