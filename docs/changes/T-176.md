# Internal documentation closeout routing

The navigator and doc-impact gate now share path normalization and the internal
closeout classification contract. `TASK.md`, the internal changelog and files
under project-memory remain internal evidence when collected from preflight or
supplied as additional documentation. Mixed scopes list only user-facing docs in
`--docs-updated`; internal-only scopes use `NO_DOC_UPDATES`. Internal changelog
and memory changes use their designated flags, including in mixed scopes.

Whitespace, slash direction, contained absolute paths and dot segments, including
relative parent aliases that return into the repository, cannot move those
internal files into user-facing documentation. Paths outside the repository and similarly named
ordinary files remain outside the reserved path contract. The gate still rejects
internal paths passed directly through `--docs-updated`, and its sensitive-scope
acknowledgement, public changelog and contradictory-claim checks are preserved.
Executable documentation classification is unchanged.

Task-scoped internal file evidence uses the existing exact task-ID reference
matcher. Evidence for `T-10`, `T-1A` or `T-1-1` cannot prove `T-1`. Project-memory
maps without task IDs retain their existing compatibility: update authority
continues to belong to the project-memory-impact gate.

The owning regression records native expected-red before production edits and
executes generated mixed and internal-only commands through the real doc-impact
CLI. Focused coverage includes collected/additional aliases, direct gate
rejection, exact task references, map-only memory and adjacent post-review,
failed-completion and post-DONE documentation routing.
