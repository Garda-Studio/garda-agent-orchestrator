# Authenticated disposable recovery metadata

The read-only recovery authority reader reconstructs the exact native selection
from the canonical bounded compact intent and existing private producer authority.
It authenticates the intent purpose and creation identity, sealed positively
known-dead local producer, current native task run and committed compact evidence.
Caller snapshots and arbitrary metadata paths cannot establish authority.

New intents retain signed surviving-parent creation anchors, owner file identity
and private authority identity. Existing valid legacy intents remain unchanged
and usable for first apply while their payload exists. Legacy missing payloads
without the retained parent anchor fail closed. New REMOVED progress frames bind
the observed parent stat after the actual successful member removal.

Native owner inspection can authenticate metadata while its payload is absent;
the existing present-payload inspection contract remains strict. Recovery metadata
always reports `absence_authorized: false`: authenticated progress and remaining
tree validation are separate required contracts. This change grants no removal,
resume, permission or key creation capability and exposes no signing bytes.

Inspection preserves payload and authority bytes. Replaced parent, payload,
owner, key or intent objects, changed run or compact evidence, tampered purpose,
malformed inventory, traversal, excess metadata and inconsistent counters reject
the read. The reader rechecks the intent, key, evidence and owner bindings before
returning its metadata result.

Affected checks cover real complete and partial first apply, legacy compatibility,
actual filesystem anchors and preservation on rejected inputs. Native acceptance
and platform coverage are recorded separately; this note claims no Windows or WSL
execution. Progress decoding, locked crash resume, producer wiring, raw evidence
migration and worktree cleanup remain separate work.
