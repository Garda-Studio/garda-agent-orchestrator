# Typed backup setting definitions

The bounded `BACKUP_SETTING_REGISTRY` owns the three existing `auto_backup`
definitions. The report compatibility facade retains their ids, keys, flags,
labels, descriptions, choices, original positions and numeric presentation bounds.
Canonical defaults still come from the existing workflow owner: disabled,
one day between scheduled backups and ten retained backups.

Typed candidates require booleans or safe integers within the existing UI bounds
(1–3650 days and 1–1000 retained backups). Accepted live/template materialization
returns one immutable field candidate through `normalizeAutoBackupConfig`.
Existing permissive config parsing and its aliases remain unchanged, including
stored positive integers above presentation bounds. Detached report options and
bounds never become validation or action authority.

The definition family performs no settings persistence, backup creation,
retention execution, cleanup, purge or WIP restore. These operations remain with
their existing guarded lifecycle and CLI owners. Owning family tests cover valid
and invalid values, defaults, both targets and presentation isolation; the
independent full 61-definition digest protects the legacy report contract.
