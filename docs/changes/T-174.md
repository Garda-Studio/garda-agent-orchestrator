# Generated runtime ownership in task scope

Generated artifacts are recognized inside the supported `runtime/` bundle-root
namespace or `garda-agent-orchestrator/runtime/` deployed namespace. A runtime
segment nested under user directories does not confer Garda ownership. This
retains `tools/runtime/reviews/helper.js`, other user prefixes and runtime source
modules, including modules with deeper runtime-like segments.

The shared predicate feeds Git-derived and explicit workspace snapshots,
classification and protected restart collection. It preserves the known receipt,
event log, report, plan, lock, mutation-generation and cache exclusions and the
source-checkout manifest exception. Foreign-looking runtime suffixes no longer
count as ownership proof; existing test controls use supported owned namespaces.
Ownership checks normalize separators and dot segments before comparing roots.

The workspace snapshot cache epoch advances to discard authenticated snapshots
produced by the previous ownership policy. A valid old cache could otherwise
retain its omitted user files despite the corrected cold snapshot. Cache HMAC,
workspace identity and Git state checks remain unchanged.

Native real-Git regressions cover tracked modifications, untracked additions,
staged modifications and genuine `R100` rename for tools paths and retained src
controls. They check automatic/staged, explicit and cached snapshots, persisted
classification and required code review. A native fixture runs compile/full-suite
before checking code-context navigation. Windows separators are lexical input
coverage on the executing host; Windows/macOS Git execution remains unverified.

Current mandatory gates provide task acceptance. Pre-fix behavioral expected-red
and migration diagnostics are source-qualified evidence, not a substitute for
fresh required reviews or post-commit audit.
