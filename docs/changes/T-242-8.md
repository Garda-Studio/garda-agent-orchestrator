# Declared validation terminal closure

Required review, completion evidence and retained post-commit coverage audit now
reconstruct the same canonical declared validation targets before accepting a
terminal boundary. Observed execution must retain a current `PASSED` result;
opaque `UNRESOLVED`, pending, rejected, stale or foreign evidence cannot close it.

Every frozen capable semantic lane must remain required and unskipped. Its
already authenticated findings report and receipt must cover each exact declared
obligation once, without an open finding or a residual risk on its source.
Disposition, follow-up creation and cached or reused PASS alone are not semantic
closure. Existing receipt, context, findings, lineage and scope authentication
remain mandatory; the terminal reader grants no independent review authority.

Native DONE inspection uses the existing read-only retained-completed contract.
Projects without declarations retain their current lifecycle. The general
technology-neutral activation remains a separate work package.
