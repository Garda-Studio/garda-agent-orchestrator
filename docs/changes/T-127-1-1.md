# Typed setting metadata compatibility foundation

The existing typed registry can carry the optional option descriptions, integer
bounds, placeholder and editability hints used by the report metadata contract.
Registration validates these presentation fields and snapshots nested option
objects. Existing entries without the fields retain their previous behavior.
Scalar admission and materialization continue through their existing callbacks.

`buildWorkflowSettingMetadata` provides the existing definition shape in registry
order, with independently mutable option copies for legacy consumers. It does
not invoke validation or materialization hooks and publishes neither callbacks,
owners nor configuration defaults. Catalog-backed and review-lane entries are
read-only in this generic projection even if their presentation input requests
editing. Ordinary editability metadata is a UI hint, never authorization for a
setting mutation; guarded owners and server transactions remain authoritative.

This foundation supports the separate native family migration children. It does
not migrate literal definitions, replace their scalar policy,
change existing report consumers or complete the registry/default/CLI/UI goals.
