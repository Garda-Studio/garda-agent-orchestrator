# Generic event caller admission

The generic `gate log-task-event` entrypoint now invokes the accepted pure
`assertGenericTaskEventAdmission` policy before creating or appending event
files or performing terminal cleanup. Generic status, split, continuation,
review, workflow and other lifecycle authority events are rejected, including
case and whitespace variations. Non-string and empty event names are rejected.

Previously, the CLI could publish `STATUS_CHANGED` and
`SPLIT_REQUIRED_LATCHED` with caller-selected details that the actual split
latch consumer accepted. The owning regression uses the same consumer to
prove rejection through the CLI and continued acceptance through unchanged
native producer APIs. Rejected calls leave existing history and cleanup paths
untouched. Informational event spelling, ordinary outcomes and the dedicated
`ORCHESTRATOR_DEFECT_ACKNOWLEDGED` admission contract remain unchanged.

The policy, its tests and T-190-1 change note are byte-preserving imports from
C4 commit `d600324b66eba5792092219e5c59b95b0918ed2b`. The existing
`lifecycle-event-types.ts` dependency is unchanged from the common e240 base;
other C4 source changes and runtime authority are not part of this import.

Verification covers the pure policy, actual CLI caller/consumer path,
terminal cleanup ordering and existing authenticated defect acknowledgement.
Linux execution is covered; Windows execution remains unverified.
