# Confirmed backup deletion through the local UI API

The authenticated `backup-delete-selected` action previews explicit snapshot IDs
and returns the exact snapshots, total size, lost recovery points and a bound
confirmation token. Execution requires the phrase `DELETE SELECTED BACKUPS` and
the token; deleting the last recovery point requires a separate acknowledgement.
The server supplies the workspace root. Client path overrides are rejected.

The existing actions-enabled, origin, token and JSON boundary remains mandatory.
The backend owns its lifecycle lock. Partial outcomes preserve requested IDs,
removed IDs and errors; inventory is current only when `inventoryRefreshed` is
true. Preview and cancellation do not remove snapshots. The dashboard selection
controls are a separate work package.

Modes must be literal strings; arrays and other coerced values are rejected before
any backend call. Audit records distinguish intent from preview, rejection and
completed/partial deletion outcomes, including IDs, errors and inventory freshness.
An outcome-audit write failure is exposed without misreporting a completed deletion.
