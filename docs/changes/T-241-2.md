# Audited task-scoped CLI test selection

`workflow show` exposes `task_test_selection.require_operator_confirmation`.
Its default is `false`, including legacy configuration that omits the section.
Changing this setting itself remains an operator-confirmed workflow mutation:
`workflow set --task-test-selection-require-operator-confirmation true|false`
uses the existing fresh confirmation contract.

For an active native task, `workflow set --task-id <id> --reason <justification>
--full-suite-command <command> --focused-required-test-path <test-file>` admits
an audited command-only selection without confirmation when the setting is
`false`. Repeat the target flag for multiple files. Declared targets must be
ordinary contained test files. An unchanged regression target needs a concrete
relationship to a planned task file in the justification. Commands use the
existing direct argv and focused validation-runner contracts; no-op interpreters,
unlisted targets, shell expressions, foreign roots and multi-setting requests
(including no-op requests) are rejected before publication.

The selector requires the canonical current worktree, one matching active task,
current resolved task-mode evidence and its integrity-checked timeline. It
rechecks the entry, task artifact, native workspace fingerprint and target bytes
before publication. Configuration, audit and protected manifest use the existing
recoverable transaction. The audit records `task_selection_command`, action time,
policy, task entry and targets rather than asserting a new human reply. With the
setting `true`, the same scoped route also requires fresh operator confirmation.

The test gate stays enabled. Compile commands, timeout/retry, profiles, review
requirements and self-guard cannot use this exemption. Audited command-only
provenance remains compatible with the existing workflow-config reader; this
child changes no current-cycle rebind consumer, shared runner implementation,
UI adapter, translations or managed guidance. Unsupported target/runner syntax
fails closed; an explicit operator-confirmed ordinary workflow mutation retains
its existing contract.
