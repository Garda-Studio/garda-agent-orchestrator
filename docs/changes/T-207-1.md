# Concurrent UI workflow settings

The UI settings adapter delegates each confirmed edit to the native `workflow set`
transaction. Configuration reads, writes, audit publication and protected-manifest
refresh remain owned by that transaction. This child adds an HTTP-to-CLI regression
test for the existing integrated behavior.

Two requests prepare their setting snapshots before separate native CLI writers
launch together. The test verifies both unrelated edits survive, other policy stays
unchanged, the audit hashes form one uninterrupted chain, the protected manifest
matches and a settings reload returns both values. Preview, invalid confirmation,
invalid token and invalid value must leave the writer uncalled and the config intact.

Coverage uses a real localhost server and materialized CLI on Linux. The launch
barrier controls overlapping request preparation; it does not simulate transaction
results or replace the native writer. This does not resolve the separate one-shot
reset authorization lifetime defect retained by T-207-2.
