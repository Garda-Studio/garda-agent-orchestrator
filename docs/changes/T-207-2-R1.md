# One-action native task-reset authority

Confirmed one-action resets have their own native admission path. They never set
`workflow-config.task_reset.enabled`, repair its receipt, or restore an earlier
setting value. The ordinary permanent audited reset setting retains its existing
meaning. Preparing an action leaves OFF unchanged; an explicit enable made later
survives action completion.

## Public native contract

`runTaskResetCommand` in `src/cli/commands/gate-flows/task/task-reset-flow.ts`
accepts one of these mutually exclusive additions:

- `oneAction: true`, with `confirm: true`, `operatorConfirmed: "yes"` and a fresh
  `operatorConfirmedAtUtc`: prepare and consume authority in this invocation.
- `prepareOneAction: true`, without `confirm` or `dryRun`, with the same explicit
  operator confirmation: return `ONE_ACTION_AUTHORITY_PREPARED` and
  `oneActionAuthority`. No task reset occurs.
- `oneActionAuthority: <returned ID>`, with `confirm: true`: consume previously
  prepared authority. Invalid supplied authority fails closed even when the
  permanent setting is ON.

All routes require the concrete task and target: `reopen: true`, `discard: true`,
or `toStatus: "TODO" | "DONE"`. Existing target-conflict validation applies.
The native CLI exposes the corresponding `gate task-reset` options
`--one-action`, `--prepare-one-action`, `--one-action-authority`,
`--operator-confirmed yes` and `--operator-confirmed-at-utc <ISO timestamp>`.
Preparation emits the ID as `OneActionAuthority: <ID>` for a local command
consumer. Treat it as action authority; do not publish or retain it in UI output,
generic diagnostics, source handoffs or shared audit copies.

The C3 adapter must validate its actual action confirmation before issuing this
authority, use the same canonical workspace/task/target and native runtime roots,
and remove both global workflow-set operations. It owns adapter implementation
and its regressions. This native repair does not accept the C3 consumer task.

## Integrity and concurrency

Authority is signed with a native Git-workspace private key, bound to canonical
workspace/Git physical identity, task, target, runtime roots and the current
task-reset scope digest. Private authority/key files are contained, ordinary,
unlinked and bounded. Copied state, forged records, traversal, altered targets,
changed task evidence and expired records are denied. The lifetime is the existing
ten-minute native confirmation budget. Original confirmation and actual issuance
times remain distinct.

The scope includes stable ordinary-file reads, recursively contained scratch
descendants (up to 4096 entries per scratch tree), and the exact aggregate-log
records belonging to this task. Changing an existing scratch file or replacing
an aggregate record without changing the line count invalidates preparation.
Unrelated tasks' aggregate additions do not invalidate this task's authority.

All confirmed native reset mutations share a per-task reset lock. Authority is
consumed under that lock before effects. Exclusive creation of a separate private
consumption claim denies replay even if authentic earlier `consumed=false` record
bytes are restored. Claims are synced before effects and never removed by reset;
incomplete claims also fail closed. Replay or concurrent same-task admission is
rejected. Failed/interrupted effects require a new explicit action confirmation.
This does not add a rollback transaction to the existing reset cleanup or freeze
unrelated lifecycle event writers.

Source and tests are portable Node/TypeScript. Actual acceptance coverage is the
current Linux runner; Windows execution is not implied by that result. No UI,
workflow schema, package, dependency, permanent permission or user-memory reset
is included.
