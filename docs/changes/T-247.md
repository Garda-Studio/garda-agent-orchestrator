# Completed-task evidence discovery cost

Completed-task batches reuse one private factory-authenticated workspace request
for equivalent audit and committed-scope discovery. Each invocation creates its
own request; no successful task proof is cached or accepted from a caller.

Before publishing any batch, current queue bytes, evidence hashes, accepted
source scopes and a fresh canonical workspace snapshot are checked again. The
Git fingerprint also binds current HEAD, staged blob changes and worktree bytes.
Any drift rejects the whole batch, including tasks read earlier in the call.
Native audit, integrity, closeout, ledger, committed-blob and file-identity
requirements remain mandatory. Mutation callers must still revalidate under
their existing locks.

The regression counts real Git subprocesses for genuinely accepted fixtures.
Additional cases mutate HEAD, the index, worktree and Git configuration between
task reads. Existing completed-task authority regressions remain unchanged.
Timeouts, retry policies and platform ownership requirements are unchanged.
