# Typed review execution setting metadata

The existing `review_execution_policy.mode` definition now belongs to
`src/core/workflow-settings/review-execution.ts`. Its read-only report projection
retains the same catalog position, stable id/key/flag, label, description and
four ordered options. The independent complete 61-setting digest continues to
cover every presentation field.

The family reuses the canonical mode list, descriptions, normalizer and default
owner. The default remains `strict_sequential`; case, surrounding whitespace and
space/hyphen aliases retain their existing canonical normalization. The implicit
legacy fallback is not an editable canonical mode. Non-string typed inputs and
unknown modes are rejected without changing existing CLI/config parsing.

Live/template materialization returns frozen candidates for the single workflow
key. It neither writes configuration nor mutates a frozen task review graph,
lane policy, catalog, routing receipt or launch authority. Existing audited
writers and immutable task snapshots remain with their current owners.

Owning tests cover every canonical mode, aliases, default identity, invalid
typed inputs, legacy exclusion, target restrictions, immutable candidates and
presentation mutation isolation. Foundation, report metadata/localization,
workflow-config and existing review-execution launch-plan tests cover the
unchanged consumers and ownership boundaries.
