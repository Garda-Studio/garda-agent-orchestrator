# Test-only RED to GREEN continuation

A test-only task could record authentic expected RED, implement a fixture change,
and pass the same test under a refreshed preflight, yet remain routed back to RED.
The navigator now permits ordinary gates after authenticating both phases in the
same task-mode cycle. The latest matching command must have current preflight and
full source-content bindings and a complete, entirely passing report containing
the exact RED case set. A later expected-failure execution also supersedes the
older GREEN, even when the classified source and preflight are unchanged.
Unrelated successful commands cannot evict the matching GREEN: collection uses
the already bounded task-event window rather than the review reader's display limit.

Historical RED must retain its signed task event, artifact and output bindings.
Its original source fingerprint must be reconstructable from the unchanged test
paths explicitly targeted by that command. A changed test, missing or tampered
output, skipped cases, GREEN without RED, or a later failed matching command
cannot complete the transition. Broader historical RED scopes that cannot be
reconstructed remain fail-closed. Existing exact-current RED still permits only
implementation. Recipe routing retains its existing contract.

This phase transition does not certify semantics or waive compile, configured
suite validation, independent reviews, completion or commit controls. The report
adapter validates each nested group with the existing bounded TAP parser. It
preserves hierarchical case identities and outcomes, ignores YAML diagnostics,
and rejects incomplete plans, diagnostics outside their owning result group, or
bailouts at every depth. No language, extension
or runner is selected from file names.

The regression uses real native task entry, classification and command records:
an unchanged asserting test first fails, a fixture implementation passes under a
new current scope, and ordinary gates become available. Controls cover missing
RED, modified retained output and changed tested source. An ignored runtime-state
input reproduces later expected RED without changing classified source; a new
current GREEN is required afterward.
Nested native executions also reject SKIP or replacement of the originally failed
child while permitting the same child after it actually passes.
