# Retained completed validation inspection

Canonical declaration readers now accept an explicit `retained_completed` inspection mode. It requires a DONE task and one current-cycle native completion event bound to the actual classified preflight path. Timeline integrity, classified scope content, admitted authority, frozen recipe/source identities, retained attempt/output/result hashes and gate-bound quality phases remain independently checked. Custom preflight and task-mode paths retain their existing authority.

The mode only reads retained evidence. Recipe execution, expected-red admission, result evaluation and quality publication keep the default active-task guard. An opaque `UNRESOLVED` result remains unresolved; reading it does not close semantic or terminal obligations.

The owning regression executes and evaluates a genuine temporary-repository declaration and publishes its quality phases. It then models closed lifecycle metadata explicitly as a fixture, checks retained obligation equality, rejects absent completion and changed target bytes, and verifies that execution and evaluation still reject DONE. This fixture is not delegated review or whole-task acceptance evidence.

Reuse, navigation and post-completion audit consumers are wired in the dependent package. Terminal enforcement and general technology-neutral activation remain separate.
