# Interpreter argument boundaries

The pure decoder separates known interpreter options and their operands from the
source file or module boundary. Script arguments after that boundary stay literal.
Ruby require operands now preserve the subsequent file boundary; unknown tools
and ambiguous option suffixes remain unresolved for independent inspection.
Stdin/inline/info modes and unsupported switches do not identify a source file.
Shell decoding uses conservative ordinary switches and actual option arity;
attached symbolic options are recognized only for Zsh. PowerShell file decoding
requires explicit `-File`; unverified forms retain the complete declaration.
Unsupported shell equals-form operands also retain the complete declaration,
including subsequent inline-command flags, instead of implying a file boundary.
Clustered switches remain visible to rejection consumers; incomplete operands
retain the unresolved declaration without indices pointing beyond the argument list.

Option-arity evidence: [Zsh invocation](https://zsh.sourceforge.io/Doc/Release/Invocation.html)
and an actual Bash `-onoclobber --version` probe that rejected the next option name.

Returned argument roles and normalized switches provide rejection inputs only.
They grant no execution permission, recipe admission, validation PASS or evidence
authority. Tool/source identity and actual validation remain separate obligations.
The decoder performs no process launch, file read or control-state mutation.

Regression cases cover frozen argv, require prefixes, numeric and encoding flags,
literal operands, module/file boundaries, unresolved inline flags and malicious
Perl module declarations. Unaccepted parent source and review findings remain
preserved separately; downstream rejection consumers are a subsequent child.
