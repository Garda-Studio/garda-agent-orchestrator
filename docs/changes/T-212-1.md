# T-212-1: Preserve unknown lifecycle sentinel state

Update and uninstall sentinel readers now return `null` only for a missing path.
Unreadable files, non-file paths, invalid JSON, non-object JSON and incorrect
types for known metadata fields raise `GARDA_LIFECYCLE_STATE_UNKNOWN` instead
of representing an absent operation. Existing containment and linked-path
checks remain in force. Valid empty or partial objects and unknown additional
metadata fields remain compatible.

The common write and remove APIs read existing state before replacing or
deleting a sentinel. Unknown state therefore preserves the original marker
bytes and blocks the update/uninstall consumers using these APIs. Existing
lifecycle locks and contained mutations retain their responsibilities; this
change does not make arbitrary external filesystem replacement atomic.

Doctor catches failed sentinel reads and reports an unhealthy diagnostic with
`update_sentinel_state` and `uninstall_sentinel_state` set to `missing`,
`present` or `unknown`. Existing metadata fields remain nullable; they must be
interpreted with the state and violations. Diagnostics do not include corrupt
JSON payloads or parser error text. Preserve an unknown marker and inspect its
bytes and filesystem access before explicit operator recovery.

The focused regressions cover malformed/non-object metadata, wrong known-field
types, unreadable directory markers, preserved writes/removals, safe doctor
diagnostics and direct update/uninstall rejection with target bytes retained.
Two valid/missing-state controls remain in the same suite. The real native
expected-red run failed 30 regressions against unchanged production before this
implementation. Affected validation also includes existing update edge cases
and doctor evidence collectors. Validation runs on Linux; Windows execution
and the separate runtime-discovery contract are outside this child.
