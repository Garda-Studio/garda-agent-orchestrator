# Clean pre-implementation parent obligations

The original parent-obligation reader distinguishes a native parent split before
implementation from a parent with captured source WIP. The clean path requires a
successful original entry, its zero dirty baseline, a later native zero-diff
preflight and no original implementation-start event. The existing task-mode
validator must also accept the original task and frozen policy snapshot. This
qualifies the recorded original clean scope; it does not invent a WIP manifest or
claim custody of unrecorded writes outside that native scope.

If that parent never executed its suite, the required command comes from the
original frozen workflow declaration, read through the contained hash-qualified
reader. A changed, missing or disabled declaration remains blocked. The declaration
is not execution evidence: an actual successful post-child native command proof
must still match its command, coverage identity and current clean final source.

Existing captured-WIP validation, previously executed command/coverage contracts,
later failures, child source, parent memory and timeline/input rechecks remain.
Nested or audit-only child corroboration is outside this change. The owning tests
mock the existing native fact, task-mode and signed-proof validators explicitly;
they test this consumer boundary, not a fabricated complete parent acceptance.
