# Generic event admission policy

The C4-owned `assertGenericTaskEventAdmission` policy reserves the canonical
native lifecycle vocabulary and authority namespaces for the native producers.
Generic informational names remain permitted without rewriting their spelling.
Casing and surrounding whitespace do not bypass reserved-name checks; empty and
non-string names are rejected.

The policy includes task/status transitions, split and continuation decisions,
gate/review/workflow authority, skill/checklist and intermediate-validation
evidence. Reserving these namespaces also protects future event names added to
the same producer contracts. The policy has no filesystem or timeline mutation
and cannot grant authority from an outcome, actor or event details.

This source component is intentionally separate from the C2-owned generic CLI
handler. T-190-2 must connect it before append or terminal cleanup and prove real
CLI/navigator rejection; T-190-1 does not complete the original admission fix.
Authenticated `ORCHESTRATOR_DEFECT_ACKNOWLEDGED` remains subject to the existing
dedicated capture validation, which must be retained during that integration.

Owning policy tests cover the current lifecycle vocabulary, concrete navigator
authority names, namespace extension, normalization, informational compatibility
and malformed input. Validation runs on Linux; Windows execution is not claimed.
