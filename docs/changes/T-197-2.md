# Required custom review lane navigation

Next-step derives required review IDs from the shared validated immutable lane set.
Custom-only and mixed requirements remain visible and participate in review context,
launch, receipt, trust and closeout routing. Built-in lanes retain their existing
presentation order; additional IDs use deterministic lexical order. The frozen
dependency graph continues to determine executable launch order and blockers.

Invalidation summaries also retain required custom lanes and their dependencies.
This changes no dependency, failed-review priority, full-suite barrier, authorization
or evidence validation rule. A present malformed or inconsistent snapshot cannot
fall back to legacy flags. Snapshot-free legacy compatibility authorizes built-ins
only; custom PASS text without current context and receipts remains insufficient.

Checks cover public navigation for custom-only and mixed lanes, a custom prerequisite
of a built-in lane, full-suite and missing-evidence blockers, scope invalidation,
forged lane flags, legacy compatibility and current failed-lane scheduling.
