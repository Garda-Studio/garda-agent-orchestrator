# Required code-review floor for full source scopes

An accepted code or mixed scope on `FULL_PATH` retains the code-review decision
derived from the frozen profile guardrails, even when raw runtime-root or
extension triggers do not recognize its source files. This changes the policy
merge, not the shared file classifier. Other optional review lanes are not
activated by the code floor.

The effective review snapshot records an explicit code-review safety-floor input
and reason. Its integrity validation and canonical reconstruction retain that
input. Contradictory scope, required-code or zero-diff bindings are invalid.
Historical snapshots without the optional floor input keep their compatibility
contract; ordinary profile/capability decisions are unchanged outside the floor.

A mandatory floor cannot silently become optional when its configured lane is
inactive: preflight fails with a specific configuration error. Existing explicit
task-required declarations remain authoritative and capability checked. Zero-diff
suppression precedes the floor; intentional `FAST_PATH`, pure documentation and
test-only scopes do not acquire it.

Native Git regressions cover 300-line changes in `scripts/widget.py`,
`src/widget.cpp` and `src/widget.vue` under fast, balanced and strict fixture
profiles, plus mixed README and non-source/fast/no-diff controls. Fast full-source
fixtures obtain native compile and full-suite evidence and verify the navigator
then requires the code-review context. Snapshot tests cover inactive lanes,
reconstruction and contradictory inputs even after rehashing. Fixture inputs and
profiles are test data; the executing task remains balanced.

Current mandatory gates record execution evidence. Linux validation establishes
host-side classification and lifecycle behavior, not compilation of those three
languages or Windows/macOS acceptance.
