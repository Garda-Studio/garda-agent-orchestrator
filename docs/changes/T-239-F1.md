# T-239-F1: Deterministic heartbeat rejection oracles

The accepted T-239 test review identified Low F-001: copied-owner and hard-link
rejection tests compared only freshly acquired bytes. A heartbeat in the same
millisecond can serialize identical metadata even if an authorization guard is
removed, so byte equality alone cannot prove that a rejected owner was untouched.

Both existing tests now observe owner write and truncation calls and require zero
calls at the rejection boundary. The open-race fixture excludes its intentional
replacement creation from the observation. Original matching metadata, physical
replacement, hard-link setup and byte/inode assertions remain in place. Mocks are
restored before filesystem cleanup. The oracles no longer depend on heartbeat
timestamp advancement or a sleep. Production code and owner schemas are unchanged.
