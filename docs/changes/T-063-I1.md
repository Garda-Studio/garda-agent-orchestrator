# Safe same-process retry after backup permission denial

Selected backup deletion now preserves a fresh-preview retry in a long-lived
backend when an individual nonrecursive unlink or rmdir fails with EACCES or
EPERM and its original path and physical snapshot remain unchanged. The original
error is still reported; a failed operation never increments successful-removal
counts or bytes. Existing selected-backup response fields and CLI APIs are unchanged.

The contained-filesystem helper classifies only errors thrown by the mutation
syscall itself. It revalidates the original containment binding and compares
device, inode, mode, creation identity, link count, size, modification time and
change time. Missing, replaced or unverifiable objects remain quarantined.
Recursive failures remain conservative because earlier members may have changed.
Validation errors, unknown I/O and callback errors do not gain retry authority
from a permission-labelled error. Existing quarantine entries are never cleared.

The public backup inventory can consequently refresh after an unchanged denied
member and accept a new preview of a healthy unattempted selection in the same
process. Partial successful unlink bytes, removed IDs, unattempted selections and
unselected recovery copies remain accurate. The caller must use the current
preview token and explicitly confirm deletion of the final recovery point.

## Trust boundaries and regression coverage

| Boundary | Authority and mutable input | Reconstruction and TOCTOU protection | Negative coverage |
| --- | --- | --- | --- |
| Permission-labelled syscall error | Existing physical containment binding; errno is untrusted classification input | Compare the original binding and exact pre/post filesystem snapshot after the failed single mutation; no success callback | Same-process EACCES/EPERM and rmdir retries; object/ancestor substitution despite EACCES; reinspection denial |
| Ambiguous or uncertain mutation | Existing process-local rejected-path registry | Preserve ancestor/descendant quarantine; recursive partial effects, unknown errors and callbacks stay rejected | Existing enumeration/replacement negatives; partial recursive denial, deleted-then-denied, unknown I/O and callback denial |
| Backup selection and retry | Native inventory-derived token, snapshot IDs, lifecycle lock and explicit confirmations | Reconstruct current inventory without reloading modules; recompute token and final recovery-point counts | Public backend same-process retry, actual partial freed bytes, stale token, final-point refusal and unrelated byte preservation |

Affected checks cover contained cleanup, bounded retained-tree compatibility,
the public backup backend, existing guarded CLI and rollback compatibility.
Native compilation, required reviews and post-commit audit remain mandatory.
Linux execution does not establish Windows, WSL or browser acceptance.

This independent repair addresses C3-FB-016. It does not complete the separate
inventory-refresh coverage follow-up T-063-F1 or the consumer UI task T-064.
