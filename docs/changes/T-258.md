# T-258 — Preserve correction invocation and review-cycle provenance

Rejected reports retain the authenticated controller invocation identifier when a
provider exposes a controller name instead of a separate provider ID. Codex
controller launches still use correction-only recovery; they do not gain authority
to attest a live provider response.

Correction audit can supersede a historical rejection after a supported
evidence-only review restart that reuses the current compile. This requires the
intact task timeline, exact current preflight and compile, hash-bound native
restart, invalidated lane and a newer independently authenticated reviewer.
Original rejected output and validation failures remain visible. A correction
after that boundary, another compile binding or unverified current review remains
blocking. The additive `superseded_by_restart_event_sha256` field names the actual
restart event; the existing compile-event provenance is retained.

Validation: focused expected-RED and unchanged GREEN, current typecheck, owning
correction/transport/audit suites and the native required independent reviews.
