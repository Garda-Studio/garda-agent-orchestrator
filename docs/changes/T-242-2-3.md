# Audited recipe admission and preflight binding

`workflow set --project-validation-contract <repository-relative JSON file>` validates declared recipes and captures contained helper/config and executable identities through the existing operator-confirmed transaction. The bounded declaration read accepts native Windows separators at the CLI boundary and stores canonical recipe paths. Existing grants, review floors and settings remain intact.

An explicit admission records `project_validation` and its approved digest even when serialized configuration is unchanged. Unrelated audited mutations retain the admission chain. Workflow schema reconstruction rejects malformed approved identity maps rather than treating them as opaque extension data.

Native preflight freezes the current audited configuration and contract digests without changing review routing. Legacy projects without declarations remain compatible. Stale bindings require a refreshed preflight; admission does not launch declared tools or close execution/semantic obligations. The local audit is procedural provenance, not protection against a malicious local writer.
