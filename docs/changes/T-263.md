# T-263: Shared native evidence during recipe inspection

Recipe quality inspection uses one synchronous, read-only batch for the current
task, native preflight, source scope and authenticated timeline. Each declared
recipe retains its own frozen identity, attempt, output, result and case
obligations. Result readers reuse the batch observations rather than repeating
the same staged-index inspection for each recipe.

The owner reconstructs every recipe at the closing boundary and rechecks the
current native task observation before returning any combined result. Changed
source, executable, approved authority, preflight or timeline rejects the batch.
An opaque in-process handle is bound to its workspace, task and inspection mode
and expires when the callback returns or throws. It cannot be reconstructed from
an artifact or retained as cross-invocation authority. Standalone result readers
retain their existing opening and closing checks.

The original Windows measurement observed 4 Git index reads for one recipe and
10 for four recipes. The owning regression requires one opening and one closing
staged-scope observation while preserving four distinct native results. Separate
regressions mutate source and append a genuine native event during retained
result reads, then verify stable recovery without rewriting history.

Process observation remains separate from independent case semantics. This does
not publish execution facts, grant permissions or skip native gates and reviews.
