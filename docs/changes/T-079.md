# ESLint explicit-any and unused-binding policy

`npm run lint` now rejects explicit `any` in source and Node test files by default.
Existing debt remains warning-only in the exact files listed in
`.eslint/legacy-explicit-any.json`. The measured pre-change inventory contained
203 occurrences in 43 files; its scope is a gradual migration, not a mass cleanup.
No directory-wide exception is added. A new neighboring file still gets errors.

These file-level exceptions also warn for new `any` in a listed legacy file;
they do not distinguish old and new occurrences. Review changed legacy code and
prefer a specific type or `unknown` with narrowing. Remove a file from the list
when its last explicit `any` is eliminated. The owning contract test rejects
obsolete exceptions, duplicate paths, globs and traversal segments.

Source and Node test unused bindings are warnings. Names starting with `_` may
mark intentionally unused variables, parameters and caught errors. Rest-sibling
omissions are allowed. Other unused parameters and caught errors are reported.
Warnings remain visible and do not fail the current lint command, which has no
`--max-warnings` limit. No rule uses automatic `any`-to-`unknown` rewriting.

The existing JavaScript correctness errors remain enabled. Build-script rules,
compiler options, package and lockfiles, workflow triggers, and other owners'
source files are unchanged. Complexity and line-limit rules are deferred because
this bounded task provides no evidence requiring another blanket warning policy.

The owning test runs the installed ESLint against synthetic new source/test
paths, a real legacy path and its neighbor, unused-binding cases, every legacy
entry, and the existing build-script boundary. Acceptance also requires actual
`npm run lint`, focused package lint-script and installed-config contract checks,
strict compile and fresh native required reviews. The broader existing
`quality-scripts` run has two independent CI-matrix assertions that currently
expect literal YAML `node-version` lists rather than the accepted expression
matrix from `9357c0878988d1df8954596a5a456088993548c3`. Their real failures are
preserved for integration handoff; that broader run is not claimed passed.
Neither the workflow nor those tests changes in this lint-policy task.

Local execution evidence covers Linux and the current Node runtime; Windows,
macOS, other Node versions and hosted CI are not claimed. CI is not required or
authorized for this local policy change.

## Integrated Fixture Type Cleanup

The current integration continuation replaces 22 explicit-any annotations in
three recovery test files with fixture-local mutable record shapes, native
filesystem argument types and an intentional invalid-input assertion. It also
removes one unused lock-preservation binding. Signed corruption payloads,
filesystem call arguments, assertions and platform skip conditions stay intact.
These fixture types describe test-produced JSON before intentional corruption;
they do not validate untrusted production records. Runtime validators and lint
enforcement remain unchanged, with no additional exception or override.

Validation includes the four owning files, the installed ESLint policy contract,
actual lint and unused-binding checks, and the native required gates/reviews.
Current task artifacts record Windows outcomes separately from the historical
Linux policy evidence above. Hosted CI and unavailable platforms are not claimed.
