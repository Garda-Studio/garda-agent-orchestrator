# T-230: trusted dashboard template contexts

Initial dashboard translations are plain text, including the search placeholder,
notice, plan modal and page title. The language identifier is also encoded in its
quoted HTML attribute. They use the existing HTML encoder; structural
template markup and intentional glyph entities remain authored HTML. Placeholder
expansion occurs once so translated `${text.key}` syntax stays literal data.

Dashboard bootstrap catalogs, language metadata and option values use the existing
script-safe JSON serializer. Closing-script strings, angle brackets, ampersands
and Unicode line/paragraph separators cannot terminate the inline script, while
JavaScript reconstructs the original strings and enabled/token values exactly.

This is bounded hardening of trusted template inputs. Synthetic translations and
tokens reproduce the sink gap; no external XSS path was established. Real action
tokens remain random hex, and shipped language packs had no triggering input.
Server admission, action authorization and the shared encoders are unchanged.

Focused regression tests precede implementation and retain native expected-red
evidence. They cover body/attribute/modal/title boundaries, literal placeholders,
missing/null compatibility, every serialized catalog and all shipped languages.
Affected validation includes dashboard assets, client helpers, theme, local server
i18n/admission and static HTML reports. A real Linux Chromium check supplements
the HTML parser boundary tests; no Windows coverage is claimed.
