# Typed project-memory setting definitions

The seven existing project-memory setting definitions now belong to
`src/core/workflow-settings/project-memory.ts`. The report adapter retains their
identifiers, keys, flags, descriptions, options, bounds and positions. Its
independent complete 61-setting presentation contract remains unchanged.

Typed candidates accept primitive booleans, canonical maintenance/read-strategy
enums and safe integers within the existing presentation bounds. Defaults come
from the workflow owner. Field materialization reuses the unchanged public
workflow validator with complete canonical defaults, including its required
full-suite section, and extracts only the selected normalized field. Existing
permissive configuration parsing remains separate and unchanged.

Live/template hooks return frozen single-field candidates. They do not persist
settings, modify companion fields, read/write/reset user memory, grant approval,
execute maintenance or retire evidence. Actual memory and protected mutation
owners still enforce their existing policy.

Behavioral tests cover all defaults and fields, positive/negative scalar and enum
paths, both integer boundaries, legacy parser compatibility, invalid targets,
immutable ownership and presentation isolation. Report and localization checks
retain the existing public metadata; schema/config tests retain owner semantics.
