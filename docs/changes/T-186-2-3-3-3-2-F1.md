# Atomic crash readiness marker

The disposable-recovery crash worker writes its complete PID and phase JSON to an
exclusive sibling file, then renames it within the same directory before pausing.
The parent's ready-path existence check therefore observes a completed record.

A portable regression exposes file creation and truncated JSON during the actual
write and requires the ready path to remain absent until publication. Existing
Linux SIGKILL scenarios at PENDING, after unlink, and before FINISHED retain their
native owner, signed-frame, physical-identity and exact-byte assertions. Those
scenarios remain Linux-only; Windows validation of the publication regression
does not establish native Linux crash acceptance.

The worker keeps its import-safe entry guard and lazy before-FINISHED snapshot
lookup. This reconciles the preserved producer draft with later accepted root
fixes and changes no production recovery API, locking contract or permissions.
