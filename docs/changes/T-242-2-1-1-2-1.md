# T-242-2-1-1-2-1: normalized inline-program URL data

The pure `rejectInlineValidationProgramUrl` helper rejects `data:` and
`javascript:` after standard URL parsing. This includes leading C0/space,
embedded ASCII tabs/newlines and protocol case normalization. It invokes no
interpreter, network request or filesystem operation.

Primitive type checks precede parsing to avoid object coercion. Only a
non-program, option-shaped argument is inspected after its first `=`.
Explicit program filenames and literal option values retain embedded scheme
text; retained Unicode characters are not treated as removed ASCII characters.

Normal return means no specific inline-URL rejection. It does not approve a
recipe, pin source identity, establish project eligibility or prove execution.
Interpreter roles and later execution/terminal obligations remain separate.

Test-first evidence records the owning test's initial missing-module failure.
Current compile, owning behavior tests and four independent review lanes must
be recorded separately before native acceptance. Parent WIP and failed review
receipts remain preserved and cannot satisfy this child's gates.
