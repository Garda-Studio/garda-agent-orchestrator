# Typed full-suite setting metadata

The nine existing `full_suite_validation` setting definitions now belong to
`src/core/workflow-settings/full-suite.ts`, using the existing typed registry.
The report adapter projects their presentation fields at the same positions as
before. Existing ids, keys, flags, labels, descriptions, option order, bounds and
placeholders remain compatible; other setting families retain their owners.

Defaults come from the canonical workflow defaults. Typed scalar admission and
candidate materialization use the existing workflow-config validator, including
command trimming and accepted enum normalization. The registry admits typed
primitive values; existing CLI/config parsing remains separate. UI upper bounds
stay presentation hints where the current validator accepts larger safe integer
values. This migration does not tighten those owner contracts.

Materialization returns frozen configuration-path/value descriptors. It does not
write configuration, approve a command, execute validation, or change protected
workflow settings. Native audited writers, task bindings and execution guards
retain authority. Test enablement, timeout/retry and defaults are unchanged.

Owning family tests cover defaults, scalar boundaries, normalization and immutable
registry ownership. Report tests preserve the independent pre-migration contract
of all 61 definitions and their interleaved order; existing manifest, projection,
workflow-config and translated catalog tests remain regression coverage.
