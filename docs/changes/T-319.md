# Legacy updater journal handoff

An installed updater can remain active while an update runs the new runtime. The older reader accepts exactly three fields per mutation intent; adding owner metadata in a nested write made that reader reject the journal when the old updater resumed.

While any active intent lacks the owner field, new nested intents retain the legacy wire shape. Both journal slots remain readable throughout the handoff. Once those operations settle, subsequent writes capture owner metadata normally. Unknown legacy owners remain active and block snapshots; this change does not infer owner death or relax journal integrity checks.

The owning regression freezes the historical three-field contract, exercises nested writes and settlement, checks both slots, and verifies that ordinary modern writes resume owner capture. Existing generation and lifecycle checks cover corruption, incomplete publication, active mutations, rollback and writer ownership. Linux-specific owner-recovery checks retain their platform qualification.
