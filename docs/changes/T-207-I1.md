# Parent navigation after a child source commit

A split-required parent can save and suspend its implementation, execute a child,
and then return to `next-step` at a different Git HEAD. The caller previously
requested capture again even when there was no implementation left to suspend.
The capture operation correctly rejected the original-HEAD identity mismatch,
which prevented routing the next child.

The caller now checks the current implementation inventory before requesting
capture. It reuses native staged/unstaged, visible-untracked and captured-untracked
collectors, including task-owned ignored temporary inputs and preflight-authorized
ignored files. Gate-owned queue metadata does not count as implementation WIP.
An invalid scope or uncertain inventory retains the native capture path.

Ignored evidence under reviews, task-events, task-ledger, project-memory, wip and
the native metrics prefix is also retained by native capture. The caller excludes
exactly these categories from its ignored-input inventory. Tracked and visible
untracked files retain their separate checks; task-owned ignored temporary inputs
and other authorized ignored inputs still require capture.

This small compatibility adapter is a bounded QG-DUPLICATION exception: the native
predicate is private on the L0/T-167-owned surface, which this repair does not edit.
Future native category changes must preserve caller parity. Integration coverage
invokes actual native capture for all six retained categories before a real child
commit, then verifies routing and unchanged retained evidence/package bytes.

An empty current inventory returns `NOT_REQUIRED`. This result does not read,
authenticate, rewrite, restore or retire a saved manifest. Current implementation
still goes through the original capture operation; deep Git HEAD, index, file
identity, containment and restore checks retain their existing authority. No
parent task mode, completion state, profile or reset permission is changed.

The owning integration regression uses a real Git child source commit after actual
native WIP suspension, verifies routing to the next balanced child and preserves
the original saved package and preflight bytes. Negative cases cover present
staged/unstaged, visible/ignored WIP, missing or foreign preflight identity and
unavailable Git. Selected advanced restore remains a separate native dry-run
contract. The affected checks also retain strict legacy and split-latch routing
coverage; platform execution is reported from the actual native test results.
Already-DECOMPOSED parent and DONE child statuses in the legacy-evidence fixture
are explicit test inputs, not fabricated native transition or acceptance evidence.
