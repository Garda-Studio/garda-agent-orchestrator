# Authenticated grouped follow-up reuse across tree changes

Grouped follow-up recovery now matches a reused receipt's original reviewer
invocation against its authenticated source tree. Strict reuse validation still
binds the current receipt and context to the new compile cycle and verifies the
historical receipt, source domain, execution contract and invocation provenance.
A different current worktree hash alone no longer invalidates accepted reuse.
Fresh receipts continue to require their current invocation tree. Missing source
trees, altered reviewer identities or sequences, forged source hashes and stale
or unbound reuse evidence remain blocking.

The owning native regression covers changed-tree materialization and child-scope
resolution, including a test-only follow-up with empty code, API and security
lanes. Existing child IDs and historical validation, disposition and invocation
evidence are preserved. Expected-red was authenticated before production edits;
normal compile, affected tests and independent review remain required.
