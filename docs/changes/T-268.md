# Native correction invocation audit binding

The retained audit now consumes the actual native correction-only invocation
event shape. The response digest comes from its native availability field and
the response-event identity from the event's integrity hash. The original
reviewer invocation remains bound through the selected correction package.

Before deriving these read-only audit facts, the consumer requires a unique
earlier correction launch with the matching task, lane, provider and corrector
identity, after the selected transport. It verifies the exact launch-input,
package and artifact digests and the original reviewer, attempt and response
bindings. Explicit conflicting legacy aliases refuse instead of falling back.
Existing legacy event handling is preserved.

Native retries retain the distinct correction producer identity. Their selected
snapshot path may be derived from the exact package digest only after the native
launch binding succeeds; explicit conflicting snapshot metadata still refuses.
Existing accepted historical postimage obligations remain unchanged.

The owning regression uses real native package persistence, the native event
shape and a distinct correction launch. Missing or reordered launch evidence,
altered response/input digests and conflicting aliases remain blocked. Existing
missing/tampered snapshot assertions remain in the same integration case.
The historical retry assertion keeps the later pending correction blocked.

No original event, report, receipt or accepted artifact is rewritten. This repair
does not waive later source or memory drift, close a parent audit, or manufacture
a historical PASS.
