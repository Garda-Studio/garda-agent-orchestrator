# Exact disposable removal after durable compact intent

Confirmed removal accepts only the exact dense native registration selection and
ownership digest from a fresh preview. It reconstructs authenticated sealed dead
producer ownership, current native run, committed closeout, compact ledger,
dependencies and the complete contained inventory under the existing lifecycle
and producer writer locks. Caller snapshots never establish deletion authority.

The immutable compact intent is retained. A separate bounded append-only progress
directory stores private ordinary authenticated frames with a distinct purpose,
their own creation identities, the intent hash and a hash chain. Each PENDING
frame is durable before its one nonrecursive removal; each REMOVED frame records
actual successful bytes and members. FINISHED requires exact complete absence.
Payload contents and signing authority are never exposed in progress.

Every remaining member, directory creation identity, file hash, dependency,
compact evidence binding, producer owner and lock generation is rechecked before
mutation. Only metadata changes caused by successful owned child removals update
the retained parent-directory stat. Added paths, replacements, changed bytes,
foreign metadata, linked storage, nested repositories, raw references and recovery
evidence preserve the remaining selection.

Failures return INCOMPLETE with explicit errors and conservative count completeness.
An authenticated ERROR frame is recorded only while current authority remains valid;
otherwise existing PENDING evidence stays protected. Existing progress and partial
payloads require the separate authenticated recovery contract. Producer wiring,
raw-evidence migration, worktree deletion and shared lock implementation are outside
this change.

Affected checks cover actual absence and byte reduction, preview/apply parity,
readable compact history, per-member ownership and dependency drift, replacements,
tampering, lock loss, fsync and unlink failures. Native Linux acceptance is recorded
separately; this note makes no Windows or WSL execution claim.
