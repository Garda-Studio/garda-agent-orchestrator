# T-203: Preserve invalid existing configuration during init

Configuration materialization now rejects existing malformed JSON, non-object
roots, and unreadable inputs instead of replacing them with template defaults.
The init configuration stage validates every managed input before its first
configuration write, including the canonical `garda.config` input. Invalid
existing workflow configuration cannot bypass validation through startup flags
that describe it as absent or preserve a legacy omission. Dry-run reports the
same input failure without writing configuration.

The shared workflow-config merge reader distinguishes genuine missing files from
inaccessible paths, non-file destinations, dangling links, and invalid ancestors.
Template synchronization rejects failure statuses with a repair instruction that
omits JSON contents. Its existing read-status API remains compatible.

Genuinely missing inputs still receive defaults. Valid partial objects retain
custom settings and receive missing keys; valid legacy omission and canonical
`garda.config` replacement policies are unchanged. The init stage keeps the exact
original workflow-config bytes when the merged object is unchanged, and uses
the existing contained destination and writer guards.

Regressions cover every managed malformed input, invalid workflow roots, startup
flag bypass attempts, mocked access/read failures, directory and dangling-link
paths, dry-run failure, valid empty-object defaults, and six unchanged workflow
serialization formats. Native test-first evidence recorded real assertion
failures before the production fix. The affected suite also covers init, reinit,
update identity, config schemas, and the full-suite configuration reader.
