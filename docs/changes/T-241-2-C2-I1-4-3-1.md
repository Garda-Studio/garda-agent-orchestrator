# Native parent audit fact selection

The lifecycle owner now exposes a read-only selector for the existing aggregate
requirements planner. It binds the canonical queue's explicit child set to the
native decomposition decision and ordered parent-completion event. Current native
child source acceptance remains owned by the existing proof reader.

Missing children or source proof, corrupt timelines, conflicting graph metadata,
reordered completion and later parent re-entry leave requirements blocked. An
ordinary leaf remains outside this selector; changing a former parent's queue
notes cannot erase its retained native split history.
Follow-up links alone do not select aggregate handling for an ordinary leaf;
selection requires a decomposed queue status or retained native parent history.
Integrity inspection precedes that applicability decision, so corrupted split-only
history cannot become an ordinary leaf by hiding its parent marker.

The result is an observation with outstanding requirements, never parent PASS.
Original full-suite obligations and failures, parent memory and preserved WIP
remain separate. A later skipped-suite event cannot erase an earlier observed
suite obligation. Actual aggregate audit application belongs to the next child;
this change neither replaces leaf gates nor adds a proof producer.

The owning test checks selection using native isolated event/decomposition
fixtures and an explicitly mocked child-source boundary. The existing source
proof suite owns genuine signed Git acceptance. Current native validation and
independent reviews remain required for this implementation.
