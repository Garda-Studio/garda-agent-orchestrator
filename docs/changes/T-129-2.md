# Separate client identity from model and instruction selection

An additive `resolveProviderClientContext` metadata API now distinguishes the
requested registry identity, concrete client, surface, reported version, model
and instruction selection. Historical DeepSeek needs an explicitly selected
concrete host instead of being treated as a standalone client. Existing stored
IDs, aliases, `SourceOfTruth`, `ActiveAgentFiles`, policy tiers, configuration and
emitted paths remain compatible; native admission callers are unchanged.

Missing/unknown/conflicting identities and reported unsupported/unavailable
operations produce explicit refusals. Unknown evidence remains `unverified`;
positive capability labels cannot create native loading or reviewer evidence.
The pure API returns immutable values and performs no file, environment,
authentication, network or reviewer operations.

Provider docs now separate structural fixture coverage from the dated primary
documentation and actual probe matrix. Current Claude settings/version caveats,
Qwen and Junie AGENTS selection, Copilot surface differences, Windsurf documentation
redirects, and Antigravity `agy` / `.agents` contracts retain explicit limits.
Other-client loading and launch are unprobed; the local Codex version probe does
not establish the existing app's version or native instruction loading.

Test-first source covers identity separation, concrete hosts, historical aliases,
immutable snapshots, input validation and unknown/unsupported/unavailable refusal
states. Actual mandatory gates and acceptance are owner-local evidence, not a
claim made by this document. Profile emission, discovery, migration, remaining
catalog alignment, hosted CI and publication are outside this child.
