# Local HTTP UI admission

Open the URL printed by `garda ui`: `http://127.0.0.1:<port>/`. The server
accepts exactly that Host and the actual listening port. Other names, including
`localhost`, foreign DNS names, missing/duplicate Host and mismatched ports are
rejected before the page can expose its session action token.
At the default HTTP port 80, both `127.0.0.1` and `127.0.0.1:80` are valid
Host authorities; browser Origin is the canonical `http://127.0.0.1`.

Every route rejects a supplied foreign or opaque Origin and browser metadata
other than `same-origin`/`none` before report projection, configuration reads or file access.
Origin-free local HTTP clients remain supported. Requests use origin-form paths;
absolute URLs and network-path targets cannot override the server's origin.

Task-action POSTs require enabled actions, JSON, the current server's token and
the exact loopback Origin before checking task IDs or reading the queue. Tokens
from another server do not authorize the request. Existing action/session error
codes remain available; rejected read APIs use `local_ui_boundary_rejected`.

Responses disable MIME sniffing and framing, restrict cross-origin resource use,
and send referrers only within the same origin. The CSP restricts frames, objects
and base URLs while preserving the dashboard's inline scripts and styles.
File previews retain their token, Origin/Referer and repository-containment
checks, serve plain text and allow contained files without extension filtering.

Validation combines genuine HTTP regression cases with a controlled Chromium
hostile-origin and loopback hostname-resolution probe. The latter verifies
browser requests under a foreign hostname; it does not claim live DNS mutation
or native Windows coverage. Acceptance evidence is retained in the task runtime.
