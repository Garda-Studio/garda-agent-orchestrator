# Selected reviewer lens reference binding

An activated review lane now binds the required string references declared in
its selected `skill.json`. Names resolve beneath the owning skill's `references/`
directory, are sorted deterministically and are bound with exact byte hashes.
The metadata file and reference paths use the existing native contained-path
identity checks. Required inputs must be ordinary files: traversal, absolute
paths, control characters, symlink/junction paths, missing files and concurrent
identity/content changes are rejected.

The limits are 32 declared files, 128 KiB per reference, 512 KiB total reference
content and 64 KiB metadata. Reads allocate only a bounded buffer and check the
opened descriptor and current path identities before returning a binding.
Nonblocking opens let the existing identity guards reject a POSIX FIFO replacing
a checked regular input; no-follow semantics also reject a leaf symlink at open.
The FIFO race is tested in an isolated, time-bounded POSIX subprocess. Windows
execution is not inferred from that fixture.
There is no recursive skill-tree scan or external link fetch. Undeclared
informational files are not reference inputs.

`selected_skill.reference_binding` is an optional schema-1 object containing the
metadata path/hash, reference root, limits and ordered required reference
path/hash/byte records. The generated context remains schema 4. A skill without
a metadata file, without references or with an empty reference list retains its
original selected-skill binding shape; historical diagnostic contexts remain
readable. Current launch and receipt admission reconstruct the selected binding
from the immutable lane candidates and current repository root, rejecting
reference drift or disappearance without rewriting the historical artifact.

The handoff's required read order names the selected entrypoint and each bound
lens file. Its prompt/output authority stays findings-only. Reference bindings
also enter the review-reuse fingerprint directly, so reference-only changes
cannot disappear when entrypoint or role-artifact hashes remain unchanged.
Canonical skill metadata is the input contract; project-specific live skills
and user memory are preserved rather than replaced by templates.

Focused tests cover deterministic hashes, declared-only inputs, JSON-only and
no-reference skills, missing/non-file inputs, escaping paths and symlinks,
count/byte bounds, real generated handoffs, current launch/receipt admission and
reference-only reuse freshness. Execution results come from the native gates;
fixture data is not runtime acceptance authority.
