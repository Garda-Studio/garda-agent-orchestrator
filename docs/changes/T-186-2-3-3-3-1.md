# Authenticated disposable recovery metadata mutation

`withOwnedDisposableRecoveryMutation` accepts exact native selection, the original
preview digest and explicit confirmation. It reconstructs the existing read-only
remaining proof before and under the unchanged lifecycle and producer-writer lock
APIs. Caller records, keys and snapshots are not inputs to this gateway. It reuses
the existing private authority, contained non-overwrite publisher, fsync and
runtime mutation generation; missing or replaced authority is never recreated.

The gateway provides a synchronous metadata mutation handle. It publishes no
payload unlink/rmdir loop and adds no producer, closeout or CLI wiring. The handle
expires when the native lock scope returns. A caller obtains only an exact retained
member from `pending()`; `removed()` requires that issued member's signed pending
record and actual exact absence. No caller-supplied path or successful count is
accepted. Public payload resume and subprocess crash/repeat-run completion are
the following child's scope.

Legacy first-apply frames keep their existing schema and meaning. New frames use
`resume_version: 1`, a hash-chained `resume_attempt` and explicit reconciliation
counters. `RESUMED` retains the pending member, clears the prior error and opens a
new bounded attempt. Legacy frames cannot reappear after extended history;
FINISHED remains terminal. At most 64 resume attempts, the derived frame allowance
and the unchanged aggregate metadata byte bound limit repeated interruption.
Transport derives its frame ceiling from the authenticated selected inventory
plus the bounded retry allowance and rejects excess membership before frame reads.

An already absent signed pending member cannot count as this invocation's removal.
`reconcilePending()` admits only that one unissued uncertainty already pending when
RESUMED opened the attempt, signs its fresh parent identity and records RECONCILED.
A newly published PENDING member that disappears before handle issue is rejected
before reconciliation publication; the preserved history can resume in a later
attempt. `known_removed_*` continues to describe
genuine signed REMOVED events; `reconciled_*` stays separate. The derived
`retired_member_count` drives exact remaining membership. Reconciliation cannot
skip the canonical order or replace a new pending removal in the same attempt.

Every append revalidates native metadata, remaining payload, dependencies and lock
generations. During the publisher's own temporary file and final rename, captured
frame generations/hashes, native authority, remaining/absent bindings and fresh
parent stats stay enforced; complete canonical membership and remaining proof are
reconstructed after publication. Unknown/interrupted metadata, replacement,
changed bytes, dependencies, run/key drift or lock loss preserve the selection.
Read-only snapshots expose their already validated parent bindings for this check
and continue to report `absence_authorized: false`.

The task's Linux validation covers genuine legacy/new transitions, exact counters,
multiple roots, finished history, caller injection, byte/creation/dependency/run/key
drift, actual publication races, lock loss, expired handles and bounded attempts.
The capacity fixture seeds correctly encoded authenticated historical frames on
fresh ordinary files with actual creation identities and current UTC time. The
production gateway exercises acceptance of attempt 64 and refusal of attempt 65;
this avoids reentering the full native lock/proof path for every historical retry.
Windows, WSL, browser and CI execution are not claimed.
