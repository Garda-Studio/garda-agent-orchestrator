# Review catalog transaction ownership

Review catalog confirmation and apply retain the existing private, exclusive
regular-file lock. New records identify the local host, PID and unique owner.
Known-dead current records recover under bounded exclusive recovery guards;
identity, exact bytes and local process liveness are checked again under the guard.

Live, foreign-host, malformed, unreadable and legacy records without verifiable
owner metadata remain preserved. No expiry, force takeover or guessed dead PID
authorizes mutation. A saturated recovery-guard chain also preserves its records
and requires explicit maintenance rather than unbounded recursion or waiting.

Release and failed-publication cleanup remain bound to the acquired descriptor
and original ordinary-file identity. A substituted marker is preserved and the
failure stays visible. Parent containment, current catalog state hashes, operator
confirmation, protected-manifest refresh and existing rollback behavior remain.
Combined operation/release failures retain both causes and surface the safe lock
release diagnostic, including descriptor identity rejection.
This is cooperative local transaction safety, not atomic exclusion against an
arbitrary external filesystem actor replacing paths between system calls.

Before production changes, authentic native expected-red recorded four failures
and three passing controls through the public confirmation API on real Linux
fixtures. Owning affected validation uses the existing review-catalog suite and
the new transaction-lock leaf. Fixtures are not real workspace consents or grants;
actual Windows execution is not claimed.
