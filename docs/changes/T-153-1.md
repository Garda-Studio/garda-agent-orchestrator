# Current built-in review skill bindings

Schema-4 built-in review contexts now use the existing selected-skill validation
that protects custom lanes. The validator reconstructs the selected entrypoint
from immutable lane candidates and the current workspace, then compares its ID,
candidate order, path, directory, existence and content hash with both the rule
context and reviewer role handoff. Missing roots, changed or removed entrypoints,
substituted candidates and catalog escapes are rejected.

This closes a reproduced gap where changing a built-in `SKILL.md` after context
generation passed the contract, tree and prompt/handoff checks shared by reviewer
launch and result receipt operations. The context bytes and scoped source tree
could remain unchanged because the live skill was outside the task's source diff.
The existing validator now blocks that case before fresh evidence is trusted.

Legacy built-in contexts keep their historical read-only diagnostic behavior.
Current coverage-required operations still reject a downgrade below schema 4.
Custom lane bindings, resolver containment and project-specific skill inputs retain
their existing contracts; the generated context shape and approval policy do not
change.

Focused regressions cover native generated contexts, downstream shared guards,
candidate and role substitution, content drift, missing/fallback entrypoints,
escaping symlinks and historical diagnostics. The existing custom-lane lifecycle
and context producer tests remain affected checks. Execution coverage is Linux;
Windows and macOS execution must be reported separately.
