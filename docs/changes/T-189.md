# Mechanical review output provenance

Gate-owned mechanical correction requires existing task, review lane, context
SHA-256 and tree SHA-256 bindings to identify the current review. A missing,
malformed or foreign binding leaves the supplied JSON unchanged and cannot
produce an accepted receipt through automatic correction. File and stdin
admission apply the same check and preserve the rejected raw input.

Schema and harmless formatting repair remain available for matching bindings:
surrounding whitespace, review lane case and SHA-256 hex case may be canonicalized.
Task identity remains case-sensitive. Findings retain their semantic fingerprint;
mechanical correction does not create provenance for an unbound review.

Regression coverage includes each binding through both input transports, missing
and invalid values, and accepted formatting-only controls.
