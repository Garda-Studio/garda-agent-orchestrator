# Canonical quality validation phases

Explicit admitted recipes add integrity-bound source/target obligations to quality evidence. Source identities, current preflight and frozen recipes are reconstructed through existing readers. Each obligation retains the latest started current-cycle attempt and its canonical result identity; stale, altered, failed and interrupted results remain rejected. Delayed evaluation of an earlier attempt cannot replace the newer execution.

Structural BOUND describes declaration/source binding. Execution OBSERVED describes a genuine completed zero-exit attempt with intact evidence; a canonical UNRESOLVED result remains UNRESOLVED and is never parser PASS. Semantics always remain PENDING_INDEPENDENT_REVIEW, including reported passing cases. Unknown syntax and natural-language descriptions therefore retain explicit independent-review obligations.

The executions array retains snapshot, attempt and result identity for every admitted recipe, including compile/typecheck/validation recipes without targets. Aggregate execution covers all recipes, so an unexecuted or failed targetless command cannot be hidden by observed test targets.

Recipe-selected quality output is PENDING_VALIDATION rather than legacy PASS/WARN. Projects without recipe authority retain their behavior and extracted template persistence. Navigation and reviewer admission consume this contract in the dependent work package; semantic/terminal closure and general activation remain separate obligations.
