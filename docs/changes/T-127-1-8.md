# Typed review-cycle setting definitions

The six existing review-cycle settings now belong to
`src/core/workflow-settings/review-cycle.ts`. The report adapter keeps their
original identifiers, keys, flags, types, descriptions, options, bounds and
catalog positions. Its complete independent 61-setting presentation contract
remains unchanged. The excluded-types description has one core definition; the
existing report text module re-exports it under its original public name.

Typed candidates accept primitive booleans, canonical action enum values, safe
integers within the existing 1–1000 presentation bounds, and dense string lists.
The current workflow owner supplies defaults. List materialization delegates
trimming, lowercasing, deduplication, unknown legacy names and the existing empty
list fallback to the unchanged guard normalizer. The existing permissive config
parser remains separate from this typed candidate API.

Live/template hooks emit only the selected frozen field candidate, including a
copied frozen excluded-types list. They do not write configuration, change a
companion limit, launch or count reviews, modify auto-split evaluation, or grant
operator authority. Existing guard, CLI and lifecycle owners remain unchanged.

Behavioral tests cover the six defaults, scalar boundaries, invalid inputs,
normalization, target rejection, immutability and presentation isolation. Report
and localization checks cover the retained public metadata and description
export; existing config and guard tests cover unchanged consumer semantics.
