# Immutable validation recipe identity

Recipe declarations remain data. Identity capture does not execute tools or issue operator permissions.
Contained regular, unshared files are read through retained descriptors with byte limits checked before allocation and closing identity checks. Executable, helper and config identities remain pinned; source/test inputs and current task scope are frozen for each recipe snapshot.
Configuration and its bounded mutation audit must identify the current config, latest explicit recipe admission and continuous intervening mutations. These local audit records provide procedural provenance, not cryptographic authority against a malicious local writer or OS confinement.
Approved maps must cover the exact declared tools and dependencies. Changed identities, foreign preflights and stale authority are rejected.
Owning validation: `tests/node/gates/project-validation/authority.test.ts`.
Workflow mutation, execution and terminal consumers are handled by subsequent tasks.
